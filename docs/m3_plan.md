## Placeholder art rule for M3 (all agents)
- **No new character modeling.** Townsfolk reuse existing models (`red_shiba`, `chr_otis`, `chr_mox`, `npc_old_zero`, enemy blockouts) with a tint/accessory swap through materials, or the simple capsule-and-sphere NPC fallback in `npc.gd`. At most an hour-cheap prop here and there.
- Sets are graybox: boxes, planes and a few reused props in the PSX look, readable from the diorama camera. Labels/colors may stand in for buildings.
- Everything loads by path and is data-driven so better art drops in later without code changes (see the style guide's Model contract).

## Shared interfaces (agree here; add to "Changes" at the bottom, never silently rename)
- **GameState** (Gameplay Programmer B is the only editor): needs `play_time_s`, `location {room, spawn}`, `story_beat`, `opened` (crate/pickup ids), `equipment` per member (`{weapon, armor, charm}` ids), `credits`, `flags`, `bag`, party member states. `to_dict()`/`from_dict()` include all of it with a `save_version`. Others call public methods; if you need a new one, ask GP-B (or add a clearly additive method and tell the integrator).
- **SaveManager** (GP-B): `save_slot(n)`, `load_slot(n)`, `auto_save()`, `has_any_save()`, `newest_slot()`, `slot_summary(n) -> {place, play_time_s, party:[{id, level}], saved_at}`, signal `saved(slot)`. Save lamps call `SaveManager.open_lamp_menu()` (or the field menu's Save page calls `save_slot`).
- **Inventory / gear** (Battle Programmer): `Equipment.equip(member_id, slot, item_id) -> bool` (owner lock, heavy armor for Otis), `Equipment.get(member_id) -> Dictionary`, `StatCalc.stats(member_id) -> Dictionary` (base + growth + gear), `ShopLogic.buy(item_id, qty) / sell(item_id, qty)` with half-price sell, 99 cap, key items unsellable. Battles read gear through StatCalc.
- **SceneRouter** (GP-A): `go_to(room_id, spawn_id)` with fade, rooms from `rooms.json`; emits `room_entered(room_id)` (SaveManager auto-saves on it); keeps the battle detach/attach working through Main.
- **Config screen** (UI-B) is one component used by both the title and the field menu's Config page (UI-A embeds it instead of its own rows).
- **Dialogue**: speech bubbles stay the main field dialogue (Ross, 2026-10-06). M3-3 adds what's missing: mid-line expression tags, fast-forward, auto-advance, a small portrait slot for named cast (placeholder initials heads until portraits), plain bottom box for crowd/signs.

## Changes

### 2026-10-07, Gameplay Programmer B (M3-9): save system
Everything below only adds. Nothing was renamed. Data: `game/data/world/save.json`, `game/data/text/save.json`, `game/data/dialogue/save.json`. Code: `scripts/core/game_state.gd`, `scripts/core/save_manager.gd`, `scripts/save/` (`save_prompt.gd`, `save_lamp.gd`), small edits in `scripts/core/main.gd`, the test room scene.

**GameState additions** (all existing methods unchanged; `to_dict()`/`from_dict()` keep working):
- `get_play_time_s()`, `tick_play_time(delta)`, and the `playing: bool` property. The autoload adds frame time while `playing` is true. Main turns it on in the field and off on the title.
- `get_location() -> {room, spawn}`, `set_location(room_id, spawn_id = "")`. **SceneRouter: please call `GameState.set_location(room, spawn)` on every room change** (or emit `room_entered(room_id, spawn_id)`, which SaveManager turns into the same call).
- `get_story_beat()`, `set_story_beat(id)`; `get_hero_name()`, `set_hero_name(name)` (the title's name entry; blank falls back to "Red").
- `mark_opened(id)`, `is_opened(id)`, `get_opened_ids()` for crates and pickups.
- `get_equipment(member_id) -> {weapon, armor, charm}` (always three keys, "" = empty; starts from the member's `equipment` in party.json), `set_equipment(member_id, slot, item_id) -> bool` (plain storage only; `Equipment.equip()` does the rules).
- `rest_party()` full HP and Juice for everyone.
- `snapshot()` / `restore_snapshot(dict)`: what Main uses for Retry. Same as `to_dict()`/`from_dict()` except play time is not rewound.
- `save_version()`, `migrate(dict) -> dict`. Current `SAVE_VERSION` is 2; the unversioned old format is version 1. To change the format: bump `SAVE_VERSION`, add `_migrate_N_to_N+1` and an entry in `MIGRATIONS`, add a fixture in `tests/fixtures/saves/`.
- `from_dict()` now loads cleanly (it resets to the starting run first, so nothing from the current run leaks in). Member fields saved: level, xp, hp, hp_max, juice, juice_max, skills, bonus, equipment (anything written with `update_member` under those keys).
- Beaten bosses and side jobs are plain flags (`set_flag`), nothing extra.

**SaveManager autoload** (`scripts/core/save_manager.gd`): `save_slot(n)` (1 to 3; slot 0 = the auto-save is refused), `auto_save()`, `load_slot(n)` (0 to 3), `continue_game()`, `has_any_save()`, `newest_slot() -> int` (-1 none; 0 = auto), `slot_summary(n) -> {slot, place, play_time_s, party:[{id, level}], credits, hero_name, saved_at}` (`{}` for an empty slot, `{corrupt: true, slot}` for an unreadable one), `slot_count()`, `slot_path(n)`, `place_name(room_id)`, `read_file(n)`, `write_atomic(path, text)`, `notify_room_entered(room_id, spawn_id = "")`, `connect_router(router)`, `open_lamp_menu(rest = false, player = null) -> SavePrompt`, `is_first_lamp_check()`, `note_lamp_check_done()`. Signals `saved(slot)`, `loaded(slot)`. Properties for tests: `save_dir`, `game_state`, `clock`, `auto_save_enabled`, `battle_active` (Main sets it; the auto-save never writes while true).
- Files: `user://saves/slot_1..3.json` and `auto.json` (project already has `use_custom_user_dir` and `custom_user_dir_name="LightsLeftOn"`, nothing new needed in project.godot). Envelope `{file_format, slot, saved_at, summary, game}`; `game` is `GameState.to_dict()`. Keys are written unsorted so the bag keeps its order.
- **Auto-save fires only from `notify_room_entered`.** In a headless run the autoload turns `auto_save_enabled` off (so the test suite never leaves an `auto.json` in the real saves folder for Continue to find); tests that want it point `save_dir` at a temp folder and switch it on. It connects itself to `SceneRouter.room_entered` if that autoload has the signal (1 or 2 arguments both work). The arrival a load produces does not write a new auto-save.
- Place names (`place_name(room_id)`): `rooms.json` `rooms.<id>.name`, else `data/text/save.json` `places`, else a tidied room id.
- A new game's place is `rooms.json` `start_room` + its `default_spawn` (GameState reads it); the story beat comes from `data/world/save.json` `new_game.story_beat`.

**Save lamp and screen:** `SaveLamp` (`scripts/save/save_lamp.gd`, extends `Interactable`; exports `rest`, `room_id`, `spawn_id`) and `SavePrompt` (`scripts/save/save_prompt.gd`). Static `SaveLamp.is_near_any(tree, point, radius = 2.0)` is for the Camp Stove rule (Battle Programmer / UI-A): the stove works only when true. The field menu's Save page can call `SaveManager.open_lamp_menu()` or `save_slot(n)` itself (it is not a save spot, so it should stay a "Save lamps only" message).
- The lamp uses the existing interact button without edits to `PlayerInteractor`: its conversation is an empty hook `lamp_check` that the lamp registers with the room's DialogueRunner itself. No change needed in `scripts/field/*`.

**Main (`main.gd`), save-related only:** Retry now calls `GameState.restore_snapshot`; `start_new_game()` (the title's Start now goes through it: resets GameState first); `continue_game() -> bool`; `can_continue() -> bool`; connects a title signal `continue_requested` if the title has one (**UI-B: add a Continue row that emits `continue_requested`, shown only when `Main.can_continue()` is true; the title scene gets Main via the `main_flow` group**); sets `GameState.playing` and `SaveManager.battle_active`. Continue goes through `SceneRouter.start_at(room, spawn)` when the router knows the saved room and spawn, else (today, for the test room's lamp) it starts the demo room and puts Red on the Marker3D named by the save's spawn. **GP-A: add `"LampSpawn"` to `test_room`'s `spawns` in rooms.json so Continue takes the router path for the test room's lamp.** Main does not call the auto-save itself; only the router's `room_entered` does.

### 2026-10-07, Battle Programmer (M3-6): gear and items
Only adds, with one unavoidable name change (see `Equipment.get_equipped`). Data: `game/data/items/items.json` (13 items + 6 key items, effects, prices, `use_in`), `game/data/items/equipment.json` (7 weapons, 5 armor, 4 charms, starting gear, heavy-armor wearers, arrow scoring). `data/battle/battle_items.json` is retired to an empty stub: battle item effects now come from items.json. `party/party.json` members now carry `equipment` (starting gear). Code: `scripts/inventory/` (`item_data.gd`, `bag.gd`, `equipment.gd`, `shop_logic.gd`), `scripts/progression/stat_calc.gd`.

All functions take an optional last argument `state: Node = null` (the GameState to use; default is the autoload; tests pass their own).

- **`Equipment.get(member_id)` is `Equipment.get_equipped(member_id, state) -> {weapon, armor, charm}`.** GDScript refuses a static function named `get` (clashes with Object.get). Everything else is as written: `Equipment.equip(member_id, slot, item_id) -> bool`, `StatCalc.stats(member_id) -> Dictionary`, `ShopLogic.buy(item_id, qty) -> bool`, `ShopLogic.sell(item_id, qty) -> bool`.
- **Equipment additions:** `unequip(member_id, slot)`, `equip_blocker(member_id, slot, item_id) -> String` ("" = fine, else `WHY_*`: unknown_member, bad_slot, unknown_item, wrong_slot, wrong_owner, too_heavy, not_in_bag, bag_full), `wear_blocker(member_id, item_id)` / `can_wear(member_id, item_id)` (owner + heavy-armor rules only, for the shop arrows), `compare(member_id, item_id) -> {can_wear, slot, arrow (1/0/-1), delta {stat: change}}`, `blocks_status(member_id, status_id)`, and pure helpers `loadout_stats / loadout_blocks / loadout_perks / loadout_score`. Gear lives in the bag: equip takes the new piece out and puts the old one back; only gear you hold can be equipped.
- **StatCalc additions:** `breakdown(member_id) -> {base, boosters, gear, total}`, `preview(member_id, slot, item_id) -> stats` (Equip menu preview), `sync_maximums(member_id, fill = {})` (re-reads hp_max/juice_max after gear or a booster; `Equipment.equip` already calls it), and for battles `total_bonus(member)` / `stats_for_member(data, member)`. The old `stats_for(data, char_id, level, bonus)` is unchanged. Boosters live in the member's `bonus`, gear in `equipment` (GameState already saves both).
- **Bag (new):** `count`, `item_ids / gear_ids / key_item_ids / ids_for_tab(tab)` (tabs `items`, `gear`, `key`), `add(item_id, qty)`, `remove`, `can_drop / drop` (never key items), `max_stack()`. **`Bag.can_use_item(item_id, context) -> bool`** with contexts `Bag.CTX_BATTLE ("battle")`, `CTX_FIELD ("field")`, `CTX_LAMP ("lamp", the field menu while at a save lamp)`; the Camp Stove is true only for `"lamp"`. `use_blocker(item_id, context) -> String` says why not, `place_allows(item_id, context)` ignores the bag, and **`Bag.use_item(item_id, target_id, context) -> {ok, reason, healed_hp, restored_juice}`** uses an item from the field menu (heals, Juice, Smelling Salts, Camp Stove, Protein Shake). Nothing is spent unless `ok`. The menu picks `"lamp"` vs `"field"` with `SaveLamp.is_near_any`.
- **ShopLogic additions:** `buy_price / sell_price (half, rounded down)`, `buy_blocker / sell_blocker -> String` (`WHY_*`: unknown_item, bad_quantity, key_item, not_for_sale, not_enough_credits, bag_full, not_owned), `can_buy / can_sell`, `max_buyable / max_sellable` for the quantity picker. Buying and selling are all or nothing.
- **ItemData (new):** `ItemData.shared()` gives names, descriptions, prices, icons and gear stats by id (`display_name`, `description`, `price`, `sell_price`, `entry`, `item`, `gear_entry`, `gear_ids(slot)`, `key_item_ids`, `battle_item_ids`, `is_key_item`, `is_gear`).
- **Battle:** `BattleSetup.from_game_state` hands each fighter's `equipment`; the controller builds stats with StatCalc and charms with the status rules (a blocked status has 100% resist), `BattleCombatant` has new `perks` and `equipment`, Progression `new_member(char_id, level, equipment = {})` accepts gear, and `apply_xp` keeps the gear bonus. `BattleData.item_data` carries the item data; `BattleData.validate()` now checks it.
- **Sim:** `feel_targets.json` `sim.gear` (loadouts by party level); `run_sim.gd --no-gear` for the old numbers; `--walkthrough` also prints the economy line and checks it.
- **For other owners:** `battle_ui_data.gd` (one line) now also reads item names from `items/items`. `MEMBER_SAVE_KEYS` already includes `bonus` and `equipment`. Enemy HP changed (see decisions.md).
